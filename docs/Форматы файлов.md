# База знаний: форматы файлов панели УООЗД

Версия 1.0 · 13.10.2026

Этот документ — полное описание форматов данных, которые принимает и отдаёт панель.
Тот же текст доступен в самой панели: кнопка **«База знаний»** в шапке (`/baza-znaniy`).

## Общие правила

| Правило | Значение |
|---|---|
| Кодировка текстовых файлов | UTF-8 (XML — с объявлением `<?xml version="1.0" encoding="UTF-8"?>`) |
| Даты в файлах | `ДД.ММ.ГГГГ` (в XML ЕИС допустим ISO `ГГГГ-ММ-ДД`, панель сама переводит) |
| Суммы | рубли, копейки через точку или запятую; пробелы-разделители разрядов допустимы |
| ИНН | 10 цифр (юрлицо) или 12 (ИП); ведущие нули значимы |
| Дубль файла | совпадение имени и контрольной суммы SHA-256 — файл повторно не вносится |
| Файл, который панель не разобрала | попадает в «Входящие и журнал» с пометкой, ничего не теряется |
| XML с `<!DOCTYPE` / `<!ENTITY` | **отклоняется** (защита от XXE), см. статью «XML» |

## 1. Заявка 1С (Excel `.xlsx` / `.xls`)

**Где используется:** ОАО «Подготовка извещения» → «+ Новая закупка»; ОПАиЗ «Эл. заявки».

**Формат «2026»:**

| Блок | Расположение | Содержимое |
|---|---|---|
| Шапка заявки | первые строки листа, пары «поле — значение» | № заявки 1С, дата, инициатор, подразделение, НМЦК, площадка, способ закупки |
| Позиции | таблица ниже шапки | Наименование · ОКПД2 · Кол-во · Ед. · Цена · Сумма · РФ-оборудование (да/нет) |
| Ответственные лица | блок после позиций | контактное лицо, e-mail, телефон |

**Формат «2027» (закрытый аукцион):** добавляются колонки «Приоритет (паспорт)», «Проректор»; позиции могут быть на нескольких листах — тогда категория позиции = имя листа.

Правила разбора: пустая строка завершает таблицу позиций; колонка «ОКПД2» — код вида `NN.NN.NN.NNN`; e-mail ответственного сопоставляется со справочником сотрудников (по адресу определяется «Фамилия И.О.»).

## 2. Реестр ОАО (Excel `.xlsx`, «Реестр <год>.xlsx»)

**Где:** файл года в папке реестра; с 2026 — заменяется таблицей `procurements` (см. архитектуру).

- Строка 1 — заголовок документа, строка 2 — шапка колонок, данные — с 3-й строки.
- Листы: **«Конкурентные»** и **«Неконкурентные»**.
- Ключевые колонки (точные заголовки): `№ ОАО` · `№ извещения` · `Предмет закупки` · `Способ` · `НМЦК` · `Ответственный` · `Площадка` · `Дата публикации` · `Дата вскрытия` · `Рассмотрение` · `Итоги` · `Договор до` · `Цена победителя` · `Экономия` · `Статус` · `Кат. см и сп`.
- `№ ОАО` — уникален в пределах года и листа (например `1535зэа`, `415р`); суффиксы: `зэа` — эл. аукцион, `зэк` — эл. конкурс, `зцп` — запрос котировок/предложений, `р` — иное.
- `Ответственный` — всегда «Фамилия И.О.» (панель сама приводит старые варианты кнопкой «Инициалы»).

## 3. Извещение (Word `.docx`)

**Где:** «Извещение» → большое поле; папки `Извещения\…\входящие`.

Распознаётся текст извещения с площадки: номер извещения, способ, НМЦК («Начальная (максимальная) цена»), даты этапов («Дата и время окончания подачи заявок», «Дата вскрытия», «Рассмотрение заявок», «Подведение итогов»), площадка, контактное лицо и e-mail. Проверка на дубль — по номеру извещения; повторный файл предлагает обновить запись.

## 4. Протокол (Word `.docx` / `.doc`)

**Где:** перетаскивание на страницу, `Протоколы\входящие`.

Распознаётся таблица участников: наименование, ИНН, цена предложения, отклонение с причиной; итоговый пункт («Победителем признать…») задаёт победителя; если итогового пункта нет — победитель определяется по наименьшей цене среди неотклонённых. Протокол с другими значениями по уже заполненным полям уходит в «На проверке» (показывается «было → станет»).

## 5. Договор (Word `.docx` / PDF)

Номер и дата договора — только из файла (из номера закупки не подставляются); цена договора; срок исполнения из текста «с … по …»; предмет — из заголовка или п. 1.1. Проверка «не тот файл»: если договор относится к другой закупке, панель спрашивает подтверждение.

## 6. Платёжка (выгрузка 1С `.txt` / PDF)

**Где:** `Панель\ОВРК\Платёжки`; имя файла — `ПП <номер> от <ДД.ММ.ГГГГ>` (любое расширение) или варианты вида `пп_152431_06022026`.

Из формата обмена с банком (1С) читаются: номер и дата ПП, сумма, ИНН получателя, назначение платежа. Сверка с реестром: сумма ≠ реестру, ИНН получателя ≠ договору, нет номера договора в назначении, ПП раньше документа без аванса, переплата, дубль номера — всё это попадает в «Ошибки в ПП».

## 7. Таблицы обмена между отделами (Excel)

| Файл | Кто отдаёт → кто принимает | Обязательные колонки |
|---|---|---|
| Таблица ОАО за неделю (договоры и ДС) | ОАО → ОВРК | № договора, дата, контрагент, цена, вид (договор/ДС) |
| Перечень платёжек бухгалтерии | бухгалтерия → ОВРК | № ПП, дата, сумма, ИНН получателя, назначение платежа |
| Маршрут согласования (таблица ОАО) | ОАО → ОПАиЗ | № заявки 1С, этап, дата, держатель |
| Потребность к СЗ (по листам) | инициаторы → ОПАиЗ | лист = категория; Наименование, Кол-во, Ед. |

## 8. XML (новый канал)

**Где:** те же точки приёма, что docx/xlsx — перетаскивание на страницу и папки «входящие». Формат определяется автоматически по корневому элементу; результат разбора идентичен разбору Word/Excel.

### 8.1. Извещение 223-ФЗ (`eis223-notice`)
Корень `<notice>`. Поля (признаются оба написания, с namespace и без):

| XML-элемент | Поле панели | Обязательность |
|---|---|---|
| `noticeNumber` / `purchaseNumber` | № извещения | да |
| `purchaseObjectInfo` | предмет | да |
| `maxPrice` / `initialSum` | НМЦК | да |
| `purchaseMethod` | способ | нет |
| `etpName` | площадка | нет |
| `publishDate`, `openingDate`, `examinationDate`, `summarizingDate` | даты этапов (ISO или ДД.ММ.ГГГГ) | нет |
| `contact/email`, `contact/phone` | контакты | нет |
| `lots/lot/okpd2` | коды ОКПД2 (несколько) | нет |

Образец: `redesign/samples/izveschenie_223fz.xml`.

### 8.2. Протокол (`eis223-protocol`)
Корень `<protocol>`: `noticeNumber`, `protocolDate`, повторяющийся `applications/application` (`participantName`, `inn`, `price`, `rejected`, `rejectReason`), `winnerName`/`winnerInn`. Если победитель не указан — выбирается наименьшая цена среди неотклонённых. Образец: `redesign/samples/protokol_223fz.xml`.

### 8.3. Табличный XML (`table-xml`)
Универсальный обменный формат: корень `<rows>`, строки `<row>`, ячейки `<col name="…">значение</col>`. Имена колонок совпадают с заголовками реестра (ст. 2): «Номер ОАО», «Предмет закупки», «НМЦК», «Способ», «Ответственный», «Дата вскрытия», «Победитель», «Цена победителя», «ИНН». Незнакомые имена сохраняются как есть (попадают в `payload`). Образец: `redesign/samples/tablitsa.xml`.

### 8.4. Ограничения безопасности
Файл ≤ 20 МБ; документы с `<!DOCTYPE`, `<!ENTITY`, XInclude **отклоняются до парсинга**; контрольная сумма SHA-256 считается всегда и участвует в защите от дублей.
