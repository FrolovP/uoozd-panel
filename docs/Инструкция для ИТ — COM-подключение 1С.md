# Инструкция для ИТ: подключение панели УООЗД к 1С через COM

Версия 1.0 · 14.10.2026

Эта инструкция — пошаговый план для системного администратора и администратора 1С.
Цель: панель УООЗД (Windows-компьютер с Python) смогла напрямую подключаться
к базе 1С через COM-соединитель (`V83.COMConnector`) и вызывать функции общего
модуля в базе.

Пример на параметрах тестового контура: сервер `mgmu-1c-app-tr`, база
`dgu_2_0_pl_27`, пользователь `UserOdata` — подставьте свои значения.

**Если платформу 1С на компьютер панели ставить нельзя** — используйте вариант
с веб-публикацией OData, там 1С на компьютере панели не нужна:
см. `docs/Подключение 1С.md`, раздел «Вариант 1».

---

## Что понадобится (чек-лист)

| # | Компонент | Где |
|---|---|---|
| 1 | Дистрибутив платформы 1С:Предприятие 8.3 (64-bit) | компьютер панели |
| 2 | Клиентская лицензия 1С (COM занимает её на время вызова) | сервер лицензий / компьютер панели |
| 3 | Python 64-bit + пакет pywin32 | компьютер панели |
| 4 | Пользователь 1С с минимальными правами | база 1С |
| 5 | Общий модуль с экспортными функциями | конфигурация 1С |
| 6 | Сетевой доступ к серверу 1С (порты 1540–1541, 1560–1591) | межсетевой экран |

Разрядность платформы 1С и Python **обязана совпадать**: у панели Python 64-битный,
значит платформа нужна 64-битная. Проверить Python: `python -c "import platform; print(platform.architecture())"`.

---

## Шаг 1. Установить платформу 1С на компьютер панели

1. Запустите `setup.exe` из дистрибутива платформы 1С 8.3 (64-bit).
2. В списке компонентов достаточно:
   - **«COM-соединение»** (обязательно — это `comcntr.dll`),
   - остальное по необходимости (сервер/клиент на компьютере панели не нужны).
3. После установки зарегистрируйте COM-открытие вручную, если установщик этого не сделал.
   В командной строке **от имени администратора**:

   ```bat
   regsvr32 "C:\Program Files\1cv8\<версия>\bin\comcntr.dll"
   ```

4. Проверка регистрации (в командной строке, на компьютере панели):

   ```bat
   python -c "import win32com.client, pythoncom; pythoncom.CoInitialize(); c=win32com.client.Dispatch('V83.COMConnector'); print('COM-соединитель 1С доступен')"
   ```

   Ожидаемый результат: `COM-соединитель 1С доступен`.
   Если «Класс не зарегистрирован» — неверный путь к `comcntr.dll` или разрядность
   не совпала с Python.

> Имя класса `V83.COMConnector` не зависит от версии платформы 8.3.x — подходит
> любая свежая 8.3. Если на компьютере несколько версий платформы, регистрируется
> одна `comcntr.dll` — регистрируйте ту, что новее.

## Шаг 2. Установить pywin32

В командной строке на компьютере панели, в тот же Python, из которого запускается
панель:

```bat
python -m pip install pywin32
```

Проверка: `python -c "import pythoncom; print('ok')"`.

При запуске панели ярлыком «Запустить демо.bat» pywin32 ставится автоматически.

## Шаг 3. Открыть сетевой доступ к серверу 1С

С компьютера панели до сервера 1С (`mgmu-1c-app-tr`) должны быть открыты порты:

| Порт | Назначение |
|---|---|
| 1540 | агент сервера 1С |
| 1541 | порт кластера (указывается в строке соединения после двоеточия) |
| 1560–1591 | рабочие процессы кластера |

Проверка с компьютера панели: `Test-NetConnection mgmu-1c-app-tr -Port 1541` (PowerShell).

> ⚠️ Если кластер работает на нестандартном порту, уточните его у администратора
> сервера 1С и укажите в подключении: `Srvr="mgmu-1c-app-tr:1541"` — именно порт
> кластера, по умолчанию 1541.

## Шаг 4. Создать пользователя 1С для панели

В режиме 1С:Предприятие (Администрирование → Пользователи) или в конфигураторе:

1. Создайте пользователя (например, `UserOdata`).
2. Аутентификация 1С:Предприятия — включена, задайте пароль.
3. Роль — **минимально необходимая**: чтение тех объектов, которые панель будет
   запрашивать. Административные права не нужны.
4. У пользователя должно быть право **«Внешнее соединение»** (корневое право в роли).

## Шаг 5. Добавить в конфигурацию общий модуль

Панель вызывает экспортные функции общего модуля. Два способа:

### Вариант А (предпочтительный): расширение конфигурации

Не меняет основную конфигурацию, не снимает её с поддержки.

1. Конфигуратор → Конфигурация → Расширения конфигурации → Создать.
2. В расширение добавьте **общий модуль**, например `УООЗД_Интеграция`.
3. Свойства модуля: **Сервер = Да**, **Внешнее соединение = Да**.
   «Привилегированный режим» — только при крайней необходимости.
4. Добавьте экспортные функции (пример ниже).
5. Обновите конфигурацию базы данных (F7).

### Вариант Б: модуль в основной конфигурации

То же самое, но модуль добавляется в конфигурацию напрямую (потребуется
включить возможность изменения).

### Пример кода модуля

```bsl
// Общий модуль УООЗД_Интеграция (Сервер, Внешнее соединение)

// Простейшая проверка связи — панель вызывает её кнопкой «Проверить»
Функция ПроверитьСвязь(Параметр) Экспорт
	Возврат "ОК, база " + Строка(Метаданные.Имя) + ", " + ТекущаяДатаСеанса();
КонецФункции

// Пример отдачи данных: панель принимает строку JSON
Функция РеестрЗакупок(Параметр) Экспорт
	Результат = Новый Массив;
	// ... запрос к документам/справочникам, заполнение структур ...
	Запись = Новый ЗаписьJSON;
	Запись.УстановитьСтроку();
	ЗаписатьJSON(Запись, Результат);
	Возврат Запись.Закрыть();
КонецФункции
```

Правила для функций:

- слово **«Экспорт»** обязательно — без него функция извне не видна;
- возвращайте **строку** (лучше JSON через `ЗаписатьJSON`), число или булево —
  объекты 1С (ТаблицаЗначений, ссылки) через COM в панель не передаются;
- параметр — одна строка (при необходимости — JSON-строка, которую функция
  разбирает через `ПрочитатьJSON`); если параметр не нужен — функция без параметров;
- имена модуля и функций — только буквы, цифры, подчёркивание (панель это проверяет).

## Шаг 6. Настроить подключение в панели

В панели: **Администрирование → «Подключение к 1С без веб-публикации» → + Подключение**:

| Поле | Значение (пример) |
|---|---|
| Название | ДГУ - тестовая |
| Сервер 1С | `mgmu-1c-app-tr:1541` |
| Имя базы | `dgu_2_0_pl_27` |
| Пользователь 1С | `UserOdata` |
| Пароль | пароль пользователя |
| Общий модуль | `УООЗД_Интеграция` |
| Функция | `ПроверитьСвязь` |

Нажмите **«Проверить»** — панель откроет COM-соединение и вызовет функцию.
Затем **«Сохранить»**.

Для файловой базы поле «Сервер 1С» оставьте пустым, а в «Путь к базе» укажите
каталог базы, например `C:\Базы\Закупки` (компьютер панели должен иметь доступ
к этому каталогу).

## Шаг 7. Диагностика типичных ошибок

| Сообщение панели | Причина и решение |
|---|---|
| `не установлен pywin32` | Шаг 2 не выполнен в том Python, из которого запущена панель |
| `Класс не зарегистрирован` / платформа не установлена | Шаг 1: нет платформы 1С, не зарегистрирована `comcntr.dll` или разрядность ≠ разрядности Python |
| `1С не ответила…` + сетевая ошибка | Шаг 3: сервер недоступен, закрыты порты, неверный порт кластера |
| `База 1С не найдена…` | Неверное имя базы (`Ref=`) или путь (`File=`) |
| `1С отклонила пользователя…` | Неверный логин/пароль, пользователю запрещён внешний доступ (шаг 4) |
| `нет лицензии` | Нет свободной клиентской лицензии на компьютере/сервере панели |
| `Общий модуль … не найден или недоступен` | Нет модуля или у него не стоят флаги «Сервер» и «Внешнее соединение» (шаг 5) |
| `экспортной процедуры/функции … нет` | Опечатка в имени или нет слова «Экспорт» |

## Безопасность

- Пароль пользователя 1С хранится в файле панели `Панель — подключения 1С прямые.json`
  рядом с панелью — доступ к этому файлу должен быть только у учётной записи,
  под которой работает панель.
- В браузер и журнал пароль не передаётся (в строке соединения он маскируется).
- Давайте пользователю 1С минимальные права: только чтение нужных объектов.
- COM-трафик между панелью и сервером 1С не шифруется — используйте в доверенном
  сегменте сети или поверх VPN/изолированного VLAN.
