# Как встроить модуль «Подготовка извещения» в основную программу

Версия модуля — 0.6.6 (`config.ini`, параметр `versiya`). Инструкция для того,
кто встраивает модуль (в том числе с помощью Claude Code). Основа — раздел 14
ТЗ. Способ встраивания выбирает владелец основной программы. Описаны оба
способа: 1 — рядом с программой (быстро, свой вид модуля), 2 — ядро внутри
программы (дольше, одно целое с пользователями и правами программы).
Разработчик модуля рекомендует способ 2.

## Из чего состоит модуль

| Папка / файл | Что это | При встраивании |
| --- | --- | --- |
| `dokumentaciya/` | **ядро**: чтение заявки (Excel/Word, в том числе .xls/.doc/.rtf), карточка, расчёты, даты, сверка отдельных файлов, сборка Word, самопроверка | не меняется |
| `lokalnyj_vhod/server.py` | локальный вход: сервер на 127.0.0.1, вызывает функции ядра; права сотрудников; журналы | способ 1 — остаётся; способ 2 — не нужен (образец вызовов) |
| `lokalnyj_vhod/prosmotr_docx.py` | экран просмотра: .docx → HTML, значения из карточки подсвечены | способ 1 — остаётся; способ 2 — по желанию |
| `lokalnyj_vhod/okno_vybora.ps1` | окна Windows «Выбор папки» и выбора файлов (поверх всех, в фокусе) | способ 1 — остаётся; способ 2 — окна программы |
| `obolochka_brauzer/` | страницы в браузере (шаблоны Jinja2, стили, скрипты, значок вкладки, без интернета) | способ 1 — показывается во вкладке; способ 2 — заменяется вкладкой программы |
| `podklyuchenie_avtonomno/tochki_podklyucheniya.py` | пять точек подключения в автономном виде (см. ниже) | заменяется настоящими точками программы |
| `dannye/` | шаблон извещения, файлы форм договора, справочники Excel, карточки закупок, настройки сотрудника, временные копии файлов | переносится на сетевой ресурс, путь — в `config.ini` |
| `kontrolnye_primery/` | заявки и ожидаемые карточки (1961/а-26, 1500/а-26, 22/а-27, 426зэа, 333зэа); `proverka.py` их прогоняет | прогнать до и после встраивания |
| `testy/` | автотесты (pytest, ставится из `requirements-dev.txt`) | прогнать до и после встраивания |
| `ustanovka/`, `Установить.bat`, `Удалить.bat` | установка в `%LOCALAPPDATA%`, обновление с сохранением данных, удаление; `znachok.ico` — значок программы (`narisovat_znachok.py` его рисует, нужен Pillow только при разработке) | способ 1 — можно использовать; способ 2 — не нужны |
| `config.ini` | путь к данным, общие папки справочников и закупок, порт, версия | путь к данным — сетевой ресурс |
| `requirements.txt` | библиотеки с точными версиями | сверить с библиотеками программы |
| `python/` | встроенный Python 3.13.15 (готовит `Подготовка.bat`); у него свои пути поиска модулей — `server.py` сам добавляет нужные папки | способ 1 — остаётся; способ 2 — Python программы |

Правило: ядро (`dokumentaciya/`) не знает ни про браузер, ни про сервер, ни про
программу. Всё общение — через шесть функций ниже и объект настроек.

## Библиотеки

`requirements.txt`: docxtpl[subdoc] 0.20.2 (с docxcompose 2.2.0 — вложенные
таблицы приложений), python-docx 1.2.0, openpyxl 3.1.5, lxml 6.1.3, Jinja2 3.1.6,
xlrd 2.0.2 (.xls без Excel), а также babel, et_xmlfile, MarkupSafe,
typing_extensions — версии в файле. Для тестов — `requirements-dev.txt` (pytest).
Excel и Word (если установлены) используются только для перевода .xls/.doc/.rtf.

## Шесть функций ядра

Все функции — в `dokumentaciya/yadro.py`. Первый аргумент у всех, кроме
`opisanie_polej`, — объект настроек `Nastrojki`.

| Функция | Что делает | Что возвращает |
| --- | --- | --- |
| `opisanie_polej(procedura="zakrytyj_aukcion")` | список полей карточки: имя, группа, подпись (метка пункта извещения), тип, обязательность — по нему строится вкладка | список словарей |
| `otkryt_kartochku(nastrojki, put_papki, polzovatel_fio=None, id_zakupki=None, nomer_zakupki=None, roli=None)` | создаёт карточку по папке закупки (читает заявку и отдельные файлы, сверяет их) или открывает сохранённую по `id_zakupki`; `roli` — роли файлов, выбранные сотрудником `{путь: роль}`; `polzovatel_fio` — кто заводит закупку (он же её ведёт). Без прочитанной заявки карточка не создаётся | состояние закупки (словарь, ключ `id`) |
| `zapolnit_iz_zayavki(nastrojki, id_zakupki, polzovatel_fio=None)` | перечитывает заявку; решения сотрудника (площадка, форма договора, подписанты, п. 1, столбцы ТЗ, ручные правки) сохраняются | состояние закупки |
| `izmenit_pole(nastrojki, id_zakupki, imya_polya, znachenie)` | меняет одно поле, помечает «изменено вручную», пересчитывает зависимые. Особые имена: `soglasovano.<i>.dolzhnost/fio`, `soglasovano.ubrat`, `utverzhdayu.dolzhnost/fio`, `kontakt.sotrudnik` (п. 1: ФИО из «Сотрудники отдела.xlsx», телефон подставляется сам; ручной ввод — `kontakt_fio`, `kontakt_tel`), `rol:<путь>`, `forma_dogovora`, `nomer_zakupki`, `<поле>[<i>]` (один пункт поля-списка — правка на экране просмотра), `opechatka.ispravit` (`{"najdeno", "ispravlenie"}` — слово исправляется везде, в том числе в расчёте НМЦК и таблицах файла ТЗ), `opechatka.ostavit` (`{"najdeno"}`) | состояние закупки |
| `proverit(nastrojki, id_zakupki)` | самопроверка: «Решить» (то, что программа не смогла определить сама, и неполные части документа), ошибки, предупреждения, возможные опечатки | словарь; `mozhno_sformirovat` — можно ли формировать |
| `sformirovat(nastrojki, id_zakupki, etap="soglasovanie", d_razmeshcheniya=None, zamena=None)` | собирает и сохраняет Word в папке закупки: `etap="soglasovanie"` — извещение на согласование и проект договора; иначе — извещение для размещения. То же, что `podgotovit_prosmotr` + `sohranit_prosmotr` подряд | `{"ok": True, "izveshchenie": путь, ...}`; если файл уже есть — `{"ok": False, "nuzhno_reshenie_fajl": имя, "pravili_v_word": [...]}`, тогда снова с `zamena="zamenit"`, `"novyj"` (новый файл «(2)» — и для извещения, и для договора) или `"otmena"`; `pravili_v_word` — файлы, изменённые в Word после сохранения программой |

### Просмотр перед сохранением

Оболочка не сохраняет сразу: «Сформировать…» открывает просмотр, сохранение —
только с него.

- `podgotovit_prosmotr(nastrojki, id_zakupki, etap="soglasovanie", d_razmeshcheniya=None, dazhe_s_oshibkami=False)` —
  собирает документы в папку карточки `_prosmotr/<этап>/`, в папку закупки ничего не пишет. Ответ:
  `{"ok", "etap", "izveshchenie", "dogovor", "imya_izveshcheniya", "imya_dogovora", "papka", "oshibki_dokumenta", "proverka"}`.
  Экран показывает документы (`prosmotr_docx.py`: значения из карточки подсвечены, `data-pole` — имя поля);
  правка подсвеченного → `izmenit_pole`, затем просмотр собирается заново.
- `sohranit_prosmotr(nastrojki, id_zakupki, zamena=None)` — копирует в папку закупки ровно показанные файлы;
  ответы те же, что у `sformirovat`. При ошибках самопроверки или `oshibki_dokumenta` — `{"ok": False, "oshibka": …}`.

### Самопроверка полноты документа

- `proverit_polnotu(nastrojki, sostoyanie)` — пункты «Решить» (входят в `proverit`): Приложение № 2 без расчёта
  НМЦК или ИТОГО ≠ НМЦД, Приложение № 3 без позиций или без таблицы характеристик из файла ТЗ, сумма позиций ≠ НМЦД.
- `proverit_dokument(put, sostoyanie, fajly_tz)` — собранный документ: приложения не пустые, нет меток шаблона
  и «None»; ошибки — в `oshibki_dokumenta`, сохранить нельзя.
- `preduprezhdeniya_zayavki(nastrojki, sostoyanie)` — предупреждения, не блокируют: согласующего нет в листе
  согласования заявки, исправленная дата КП, входящие номера КП не по порядку дат, возможно потерянные степени
  в таблице характеристик.
- Расчёт НМЦК «по позициям» (лист «Расчет НМЦК», как 426зэа) — `znacheniya["_nmck_poz"]`, вставляется в
  Приложение № 2 таблицей; таблицы отдельного файла ТЗ (`fajly_tz_zakupki`) — в Приложение № 3 целиком.

### Дочитывание старых карточек

`dochitat_iz_zayavki(nastrojki, id_zakupki, soobshchit=False)` — если заявка не
менялась, но в карточке нет данных, которые программа теперь читает (расчёт
НМЦК, источник финансирования, лист согласования…), — дочитать их, не трогая
решения сотрудника; возвращает, что дочитано. Карточка помнит `versiya_chteniya`;
если она меньше `VERSIYA_CHTENIYA` (сейчас 2), оболочка молча дочитывает при
открытии. «Заполнить из заявки» при неизменной заявке дочитывает и показывает
«Дочитано из заявки: …».

### Пользователи и «ведущий» закупки

- Пользователь — сотрудник, выбранный на экране «Кто вы» (или `polzovatel` из точки 1). «Запомнить меня» —
  `dannye/nastrojki/polzovatel.json` (`polzovatel.py`).
- **Ведущий** закупки — `sostoyanie["sotrudnik"]`: тот, кто завёл её в программе (`otkryt_kartochku`,
  `sotrudnik_istochnik = "zavel"`). Меняется только `peredat_zakupku(nastrojki, id_zakupki, fio)`
  («Передать…», `"peredano"`). Ответственное лицо п. 1 (`kontakt_fio`) на ведущего не влияет. Старым карточкам
  без ведущего оболочка ставит сотрудника, выбранного на этом компьютере (`"vybran_na_kompyutere"`).
- Руководитель — «да» в столбце «Руководитель» справочника «Сотрудники отдела.xlsx»
  (`izvlechenie_excel.zagruzit_rukovoditelej`). Сотрудник видит только свои закупки, руководитель — все
  («Мои / Все сотрудники», столбец и фильтр «Сотрудник»), чужие — только для просмотра. Правила — в `server.py`
  (`prava_na_zakupku`, `_zapret`); в способе 2 программа применяет свои права.
- Одновременная правка: `zanyat_kartochku` / `kto_otkryl` / `osvobodit_kartochku` — файл `zanyato.json`
  в папке карточки (`{"fio", "komp", "vremya"}`, действует 3 минуты, оболочка продлевает раз в минуту);
  открыта у другого — только просмотр «Сейчас открыта у <ФИО>».

### Остальное (используется оболочкой, программе по желанию)

- `proverit_papku(nastrojki, put_papki, polzovatel_fio=None, roli=None)` — что решить до создания карточки:
  `oshibka_zayavki`, `neopredeleny` (файлы без роли), `rashozhdeniya`, `mozhno_srazu`;
- `najti_po_papke`, `sobrat_documenty`, `spisok_zakupok`, `dobavit_fajly_v_papku`, `pereschitat_dokumenty`;
- `najti_izmeneniya_zayavki` / `primenit_izmeneniya_zayavki` (заявка изменилась после согласования: «было → стало»),
  `sohranit_snimok_zayavki`, `zakupka_razmeshchena` (удаляет карточку, файлы в папке закупки не трогает);
- таблица ТЗ: `postroit_tablicu_tz` (видимые столбцы в действующем порядке; ПП № 1875 — последним; служебные,
  например источник финансирования, скрыты, пока сотрудник не вернул), `tz_izmenit`, `tz_izmenit_znachenie`;
- справочники: `zagruzit_ploshchadki`, `zagruzit_podpisantov_spiska`, `zagruzit_soglasuyushchih`
  («Подписанты» с ролью «согласует» и «Подразделение — согласующий»), `sotrudniki_po_alfavitu`;
- даты размещения: `data_razmeshcheniya_po_umolchaniyu`, `pervaya_dostupnaya_data_podachi`,
  `dni_mesyaca_dlya_podachi`, `poyasnenie_sroka_podachi`;
- опечатки: `opechatki_zayavki` (возможные опечатки по предмету, нацрежиму, позициям),
  `vozmozhno_poteryany_stepeni` (степени, набранные обычными цифрами, в таблицах файла ТЗ);
- мелочи для экрана: `nomer_iz_nazvaniya_papki` (номер закупки из имени папки),
  `format_nomer_i_data_zayavki`, `sokratit_fio` («Фамилия И.О.»), `papka_dostupna`
  (есть ли папка — с ожиданием не дольше 2 с).

Исключения (текст — по-русски, для сотрудника):
- `ZayavkaNeProchitana` — заявка не найдена или не прочитана, карточка не создаётся;
- `KartochkaBezDannyh` — действие с карточкой без данных заявки;
- `ValueError` — закупка не найдена или неверное значение поля.

В способе 1 сервер показывает эти тексты на экране. Остальные ошибки он
пишет в `zhurnal/oshibki.log` и показывает понятную страницу, программа не падает.

## Пять точек подключения

Все пять — функции в `podklyuchenie_avtonomno/tochki_podklyucheniya.py`.
Ядро получает их через
`Nastrojki(put_dannyh, put_zakupok=None, tochki=None, put_obshchih_spravochnikov=None, put_obshchih_zakupok=None)`:
`tochki` — любой объект с этими пятью функциями и константой
`VYKLYUCHENO = "выключено"`; если не передан — автономные заготовки.
К ИИ, OCR и данным программы ядро обращается только через `nastrojki.tochki`.

| Функция | Что передаёт программа | Ответ | Автономно | Где ядро вызывает |
| --- | --- | --- | --- | --- |
| `nastrojki()` | путь к данным, общие папки справочников и закупок, папку карточек, пользователя, порт, версию | словарь `put_dannyh`, `put_obshchih_spravochnikov`, `put_obshchih_zakupok`, `put_zakupok`, `polzovatel`, `port`, `versiya` | из `config.ini` (`put_dannyh`, `папка_справочников`, `папка_закупок`, `port`, `versiya`); пользователь — экран «Кто вы» | `lokalnyj_vhod/server.py` при запуске |
| `raspoznannyj_tekst(put_fajla)` | текст PDF или скана от OCR-сервера | строка | `"выключено"`: PDF — роль «Не используется» | список файлов закупки: текст сохраняется у документа |
| `dannye_proverki_zayavki(put_zayavki)` | данные вкладки проверки заявки | `{имя поля карточки: значение}` | `"выключено"`: всё читается из файла заявки | чтение заявки: значения программы заменяют прочитанные |
| `sopostavlenie_stolbcov(zagolovki)` | разбор таблицы позиций | `{заголовок в заявке: заголовок для карточки}` | `"выключено"`: заголовки как в заявке | чтение заявки: столбцы позиций переименовываются |
| `vyzov_ii(vopros)` | «вопрос → ответ» | строка | `"выключено"` | пока нигде: шагов, которым нужен ИИ, нет |

Обязательна только точка 1. Остальные подключают по одной: функция программы
возвращает данные вместо `"выключено"`, код ядра не меняется (раздел 14 ТЗ,
правило 4). Проверяет `testy/test_tochki_podklyucheniya.py`.

### Распознавание PDF и ИИ — функции сервера основной программы

Без сервера модуль полностью рабочий: заявки Excel/Word читаются сами, документы
собираются, ИИ ни для одного шага не нужен. Распознавание PDF (точка 2) и ИИ
(точка 5) включает основная программа — своими функциями в файле точек:
`raspoznannyj_tekst(put_fajla)` передаёт файл её OCR-серверу и возвращает текст,
`vyzov_ii(vopros)` — вопрос её слою выбора провайдера ИИ и возвращает ответ.

Как это видит сотрудник:
- точка не подключена (`"выключено"`) — функции серые: PDF в списке файлов закупки —
  серой строкой «Включается при подключении к серверу распознавания», в карточке
  «Функции сервера: Распознавание PDF — …, Помощь ИИ — Включается при подключении к серверу ИИ»;
- точка подключена и сервер отвечает — PDF распознан (текст сохраняется у документа),
  подпись «подключено»;
- точка подключена, но сервер не отвечает (функция выбросила исключение или вернула
  `NEDOSTUPEN = "недоступен"`) — та же серая подпись и «Сервер недоступен, попробуйте позже»,
  без ошибок; модуль работает дальше сам (факт — в журнал событий).

Все вызовы точек 2–5 идут через `Nastrojki.vyzvat_tochku(imya, *argumenty)` →
`(состояние, ответ)`, состояния `vyklyucheno` / `nedostupen` / `rabotaet`. Подключён ли
ИИ, оболочка узнаёт `sostoyanie_ii(nastrojki)`: короткий вопрос «Проверка связи…»
через `vyzov_ii`, ответ запоминается на минуту — функция программы должна отвечать на
него быстро. Распознавание PDF повторяется, когда в карточке добавляют файлы (`pereschitat_dokumenty`).

Общие папки (ожидание не дольше 2 секунд):
- `папка_справочников` недоступна — берутся локальные справочники,
  `nastrojki.preduprezhdenie_spravochniki` — текст предупреждения для экрана;
- `папка_закупок` недоступна — карточки в `put_zakupok` (локально),
  `nastrojki.preduprezhdenie_zakupki` = «Общая папка закупок недоступна, закупки сохраняются только на этом компьютере.»;
  доступна — `nastrojki.put_zakupok` указывает на неё, `nastrojki.obshchaya_papka_zakupok = True`.

## Старые форматы файлов

`dokumentaciya/staryj_format.py`: .xls, .doc и .rtf перед чтением переводятся в
.xlsx/.docx через установленные Excel и Word. Перевод идёт без окон, только
чтение, макросы выключены, ограничение по времени. Если Excel или Word нет —
запасной способ (xlrd, свой разбор текста). Копии лежат в `dannye/vremennoe`,
в папке закупки ничего не создаётся. Сотруднику о формате ничего не сообщается;
факт перевода пишется в журнал событий (логгер `podgotovka_izveshcheniya`).
Сообщение сотруднику — только если файл защищён паролем или повреждён.

## Журналы

`zhurnal/oshibki.log` — ошибки, `zhurnal/sobytiya.log` — служебные события.
Каждый ограничен 1 МБ: больший файл становится `….старый.log` (прежний старый
удаляется). Во встроенном режиме программа может подключить свой обработчик к
логгеру `podgotovka_izveshcheniya`.

## Способ 1 — рядом с программой

1. Резервная копия программы.
2. Полный архив `Podgotovka-izvescheniya_0.6.6_polnyj.zip` → `Установить.bat`
   (программа в `%LOCALAPPDATA%\Подготовка извещения`; ярлыки на рабочем столе и
   в «Пуск», пункт «Подготовить извещение» в меню папки — со значком программы).
   Либо папку модуля положить рядом с программой целиком, с `python/` — его
   готовит `Подготовка.bat`. Свои библиотеки — конфликтов версий нет.
3. В `config.ini` указать `put_dannyh` (или `папка_справочников`, `папка_закупок`) —
   общие папки на сетевом ресурсе. Значения пользователя в `config.ini` при
   обновлении сохраняются.
4. Программа запускает модуль: `python\pythonw.exe lokalnyj_vhod\server.py`
   (без консоли), `python\python.exe …` или `Запуск.bat`. Сервер пишет порт в
   `zapushcheno.json` в папке модуля. Порт берётся из `config.ini`, если занят —
   следующий свободный. Повторный запуск открывает страницу уже запущенного.
5. Во вкладке «Документация» программа показывает `http://127.0.0.1:<порт>/`.
   Сразу новая закупка по папке: `/novaya-zakupka?put=<путь, закодированный для адреса>`
   (если решать нечего, откроется карточка; если сотрудник не выбран — сначала «Кто вы»).
6. Проверка: `Проверка.bat` — «Все примеры прошли»; затем одна-две настоящие
   закупки на установленной версии, запущенной ярлыком.

## Способ 2 — ядро внутри программы

1. Скопировать `dokumentaciya/` в программу; поставить библиотеки из
   `requirements.txt` (сверить версии с программой, конфликты устранить до
   подключения).
2. Создать `Nastrojki(put_dannyh=…, put_zakupok=…, tochki=<точки программы>, put_obshchih_spravochnikov=…, put_obshchih_zakupok=…)`.
3. Вкладку построить по `opisanie_polej()` и вызывать функции так же, как
   `lokalnyj_vhod/server.py` (готовый образец всех вызовов, включая просмотр
   перед сохранением, права сотрудников и дочитывание). Окна выбора папки
   и файлов — средствами программы.
4. Прогнать `testy/` и `kontrolnye_primery/proverka.py` внутри программы — все
   должны пройти.

## Данные — одинаковые в обоих режимах

- `dannye/shablony/zakrytyj_aukcion.docx` — шаблон извещения (метки docxtpl).
- `dannye/dogovory/` — файлы форм проекта договора (.docx).
- `dannye/spravochniki/` — справочники Excel: подписанты (столбец «Роль»),
  сотрудники с телефонами и столбцом «Руководитель», площадки, подразделение →
  согласующий, производственный календарь, формы договора, стандартные
  требования, словарь для проверки опечаток. В «Формы договора.xlsx» столбец
  «Форма-заглушка» = «да»: в карточке пометка, в договоре «ОБРАЗЕЦ — форма в
  разработке». Лист «Как заполнять» — для человека. При обновлении справочники
  не заменяются; новый столбец дописывается в конец, если это безопасно
  (`ustanovka/obnovlenie.py`).
- `dannye/zakupki/<id>/kartochka.json` — карточка до «Закупка размещена» (или в
  общей папке `папка_закупок`): данные заявки, решения сотрудника, ведущий
  (`sotrudnik`), порядок столбцов ТЗ, снимок заявки, `versiya_chteniya`; рядом
  `zanyato.json` (кто сейчас правит), `_prosmotr/` (документы экрана просмотра),
  `_vrem/` (вложенные таблицы при сборке).
- `dannye/nastrojki/` — запомненный сотрудник (`polzovatel.json`) и последняя
  выбранная папка (`poslednie_papki.json`).
- `dannye/vremennoe/` — временные копии файлов старых форматов (можно удалять).

## Проверка после встраивания

- `Проверка.bat` (или `python kontrolnye_primery\proverka.py`) — «Все примеры прошли».
- `python -m pytest testy` — все тесты зелёные (в том числе `test_vstraivanie.py`: эта инструкция соответствует коду).
- Журналы — `zhurnal/oshibki.log`, `zhurnal/sobytiya.log`.
