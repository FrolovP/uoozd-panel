1. Заявка 1С (Excel .xlsx/.xls)

ОАО «Подготовка извещения» → «+ Новая закупка»; ОПАиЗ «Эл. заявки».

БлокРасположениеСодержимое
Шапкапервые строки, пары «поле — значение»№ заявки 1С, дата, инициатор, подразделение, НМЦК, площадка, способ
Позициитаблица ниже шапкиНаименование · ОКПД2 · Кол-во · Ед. · Цена · Сумма · РФ-оборудование
Ответственныепосле позицийконтактное лицо, e-mail, телефон

Формат «2027» (закрытый аукцион): добавляются «Приоритет (паспорт)», «Проректор»; позиции на нескольких листах — категория позиции = имя листа. E-mail ответственного сопоставляется со справочником сотрудников.

2. Реестр ОАО (Excel «Реестр <год>.xlsx»)

Строка 1 — заголовок документа, строка 2 — шапка, данные — с 3-й строки. Листы: «Конкурентные», «Неконкурентные».

Колонки (точные заголовки): № ОАО · № извещения · Предмет закупки · Способ · НМЦК · Ответственный · Площадка · Дата публикации · Дата вскрытия · Рассмотрение · Итоги · Договор до · Цена победителя · Экономия · Статус · Кат. см и сп.

№ ОАО уникален в пределах года и листа (1535зэа, 415р). Ответственный — всегда «Фамилия И.О.».

3. Извещение (Word .docx)

Текст извещения с площадки. Распознаются: номер, способ, НМЦК («Начальная (максимальная) цена»), даты этапов («Дата и время окончания подачи заявок», «Дата вскрытия», «Рассмотрение заявок», «Подведение итогов»), площадка, контакты. Проверка на дубль — по номеру извещения.

4. Протокол (Word .docx/.doc)

Таблица участников: наименование, ИНН, цена, отклонение с причиной. Итоговый пункт («Победителем признать…») задаёт победителя; без него — наименьшая цена среди неотклонённых. Протокол с другими значениями по заполненным полям уходит «На проверке» («было → станет»).

5. Договор (Word .docx / PDF)

Номер и дата — только из файла; цена договора; срок исполнения из «с … по …»; предмет — из заголовка или п. 1.1. Договор от другой закупки — панель спрашивает подтверждение.

6. Платёжка (выгрузка 1С .txt / PDF)

Имя файла: ПП <номер> от <ДД.ММ.ГГГГ> (расширение любое) или пп_152431_06022026.

Из формата обмена с банком читаются: № и дата ПП, сумма, ИНН получателя, назначение платежа. Ошибки сверки — в разделе «Ошибки в ПП»: сумма ≠ реестру, чужой ИНН, нет № договора в назначении, ПП раньше документа без аванса, переплата, дубль номера.

8. XML — протокол (eis223-protocol)

Корень <protocol>: noticeNumber, protocolDate, повторяющийся applications/application (participantName, inn, price, rejected, rejectReason), winnerName/winnerInn. Если победитель не указан — наименьшая цена среди неотклонённых.

8. XML — табличный (table-xml)

Универсальный формат: корень <rows>, строки <row>, ячейки <col name="…">значение</col>. Имена колонок — как в реестре (раздел 2): «Номер ОАО», «Предмет закупки», «НМЦК», «Способ», «Ответственный», «Дата вскрытия», «Победитель», «Цена победителя», «ИНН». Незнакомые имена сохраняются как есть.

8. Ограничения безопасности XML

XML с <!DOCTYPE, <!ENTITY или XInclude отклоняется до парсинга (защита от XXE). Размер файла — до 20 МБ. SHA-256 считается всегда и участвует в защите от дублей.

9. Контур 1С — подключение

Всё управление — в «Администрирование» (только для администраторов): «Настройка источников» → подключения, «Сопоставление и синхронизация» → загрузка документов, таблица сопоставления, перенос в реестры, мастер маппинга и журнал.

ТранспортЧто этоЧто нужно на стороне 1С
OData (рекомендуется)панель читает базу по стандартному интерфейсу OData: https://<сервер>/<база>/odata/standard.odata/в конфигураторе: Администрирование → Публикация на веб-сервере, включён флажок «Публиковать стандартный интерфейс OData»; пользователь 1С с правом чтения нужных документов; веб-сервер (Apache/IIS) после публикации перезапущен
MCP-проксичтение через внешний MCP-инструмент, который сам ходит в 1Сзапущенный MCP-сервис и имя объекта метаданных (оно же — тип документа)

Кнопка «Проверить» у источника запрашивает адрес и $metadata — так подтверждаются и доступность, и публикация целиком. Пароли хранятся только в папке панели и в браузер не отдаются.

Прямой запуск 1С через COM удалён из панели. Если источник создан давно и помечен «COM (удалён)» — пересоздайте его на OData или MCP.

9. Развёртывание OData с нуля — пошагово для ИТ

Сценарий первичного подключения боевой базы 1С к панели. Время — 20–30 минут. Нужны: доступ к конфигуратору 1С с правами администратора, доступ к веб-серверу (Apache или IIS), учётная запись 1С для панели.

Шаг 1. Создать пользователя 1С для панели

Администрирование → Пользователи → новый пользователь (например, UserOdata). Дать роли с чтением объектов, которые панель будет загружать (документы закупок, договоры, справочники контрагентов). Права на изменение не нужны — панель только читает. Задать пароль, снять флажок «Показывать в списке выбора» по желанию.

Шаг 2. Включить публикацию OData в конфигураторе

Конфигуратор → Администрирование → Публикация на веб-сервере:

ПараметрЗначение
Веб-серверваш Apache 2.4 / IIS
Каталог публикациинапример, C:\inetpub\dgu_2_0_pl_27
Публиковать стандартный интерфейс ODataвключить — без этого адрес …/odata/standard.odata/ будет отвечать 404
Публиковать доступ по HTTPSрекомендуется; самоподписанный сертификат допустим — в источнике панели есть флажок «не проверять сертификат»

Нажать «Опубликовать», затем перезапустить веб-сервер (httpd -k restart для Apache / iisreset для IIS) — без перезапуска публикация не подхватывается.

Шаг 3. Проверить публикацию вручную

С компьютера, где работает панель, открыть в браузере (будет запрос логина/пароля пользователя из шага 1):

https://<сервер>/<база>/odata/standard.odata/$metadata

Должен вернуться большой XML со списком EntitySet (Document_…, Catalog_…). Если 404 — публикация не применилась (шаг 2); если 401 — логин/пароль; если таймаут — сеть/порт/брандмауэр.

Шаг 4. Создать источник в панели

Панель → Администрирование → Настройка источников → «+ Источник»:

ПолеЧто ввести
ТранспортOData
Адресhttps://<сервер>/<база>/odata/standard.odata/ — обязательно с /odata/standard.odata/ и завершающей косой чертой
Логин / парольпользователь из шага 1
Не проверять сертификатвключить, если сертификат самоподписанный

Нажать «Проверить» — ожидаем «Подключение работает: Сервер ответил HTTP 200» и список наборов данных. Сохранить.

Шаг 5. Первая загрузка документов

Администрирование → Сопоставление и синхронизация → «Загрузка документов из 1С»: выбрать источник, тип документа (например, Document_ЗаказПоставщику), небольшой период (месяц) → «Загрузить из 1С». Контроль: «прочитано N, новых N», в таблице — номера, даты, признак проведения. Затем «Показать загруженные» — документы во внутреннем хранилище.

Шаг 6. Сопоставление и перенос (по необходимости)

В «Сопоставление реквизитов документов» добавить строки: реквизит 1С → реестр и колонка панели. Затем «→ Перенести в реестры» → сначала «Предпросмотр» (ничего не пишет, показывает «изменится / без изменений / строка не найдена»), и только потом «Применить».

Шаг 7. Автоматика (опционально)

Если нужна регулярная синхронизация в реестр ОАО: мастер «+ Сопоставление» (источник → колонки реестра, ключ GUID), режим «авто», расписание в «Расписание авто-синхронизации». Каждый прогон пишется в «Журнал прогонов».

Чек-лист при «404 на $metadata» после обновления конфигурации 1С: обновление могло снять публикацию — повторить шаг 2 (публикация + перезапуск веб-сервера), затем шаг 3.

9. Методы получения данных из 1С

Как панель забирает данные из базы 1С — короткая шпаргалка по проверенным приёмам.

МетодСуть
Карта объектовGET …/odata/standard.odata/$metadata → список наборов (Document_*, Catalog_*…) и их реквизитов; из него панель строит список типов и подсказывает поле даты
Чтение документовпостранично: $top=500&$skip=…, сортировка по полю даты desc, не более 5000 за загрузку; формат — JSON ($format=json)
Фильтр периодасерверный: $filter=Date ge datetime'ГГГГ-ММ-ДДT00:00:00' and Date le datetime'…T23:59:59'
Внутренние документы ДОнабор Catalog_ВнутренниеДокументы; «тип» — реквизит ВидДокумента_Key. Фильтр по виду только на стороне панели: боевые базы отвечают 500 на сравнение ссылки с guid-литералом в $filter
Виды документовосновной путь — справочник Catalog_ВидыВнутреннихДокументов; если не опубликован (404), виды собираются из последних 1000 документов, имена — из локального словаря псевдонимов (кнопка ✎)
Адресация записиключ — Ref_Key (GUID); ссылка тонкого клиента e1cib/data/Справочник.ВнутренниеДокументы?ref=<GUID> подтверждает, где лежит объект
Внутренний справочник типовпри каждом удачном чтении типов панель сохраняет их в «Панель — типы документов 1С.json»; если база недоступна, список типов показывается из этого справочника с пометкой о дате снимка

9. Загрузка документов из 1С (внутренние документы)

«Сопоставление и синхронизация» → карточка «Загрузка документов из 1С». Выбираете источник, отмечаете один или несколько типов документов (кнопка «выбрать типы ▾») и период «с … по …», нажимаете «Загрузить из 1С» — типы грузятся по очереди, итог суммируется.

ПравилоЗначение
Список типовчитается из $metadata базы; наборы Document_* помечены как «документ», у каждого подсказано поле даты (обычно Date); выбор запоминается для каждого источника
Мультивыборгалочки «выбрать все / снять все»; клик по строке делает тип активным — он используется для переименования вида (✎) и переноса в реестры
Периодфильтр по полю даты: Date ge datetime'ГГГГ-ММ-ДДT00:00:00' … le …T23:59:59; период можно не задавать — тогда читается всё (до лимита)
Чтениестраницами по 500 документов, не более 5000 за одну загрузку
Хранилищефайл «Панель — документы 1С.json» в папке панели; ключ записи — тип документа + GUID (Ref_Key); повторная загрузка обновляет уже полученные документы, дублей не создаёт
Что сохраняетсяномер, дата, признак «проведён», до 120 реквизитов документа (каждый — до 500 символов), дата загрузки
Просмотр«Показать загруженные» — таблица с фильтром по отмеченным типам и периоду; кнопка ⇄ открывает документ как образец для сопоставления реквизитов, ✕ удаляет документ

Результат загрузки: «типов обработано / прочитано из 1С / новых / обновлено» и ошибки по типам, если были.

Внутренние документы 1С:Документооборот

В ДО документы («Заявка на закупку», «Заявка на потребность», «Протокол»…) — это не объекты «Документ», а элементы справочника ВнутренниеДокументы: видно по ссылке вида e1cib/data/Справочник.ВнутренниеДокументы?ref=…. Тип такого документа — значение его реквизита «Вид документа» (справочник «Виды внутренних документов»).

Поэтому панель предлагает внутренние документы в списке типов по видам. Выборка идёт из набора Catalog_ВнутренниеДокументы: серверно — период по «Дата регистрации» (или «Дата создания»), вид отбирается на стороне панели (часть редакций 1С отвечает 500 на сравнение ВидДокумента_Key с guid-литералом — поэтому фильтр по виду не уходит в запрос). Номером считается «Регистрационный номер», иначе — код элемента.

Если справочник «Виды внутренних документов» не опубликован в OData, панель собирает список видов из самих документов (последняя 1000) и показывает их как «Вид bc400050…». Задайте понятное имя кнопкой ✎ рядом со списком типов — оно сохранится в файле «Панель — виды документов 1С.json». Для полного списка видов с именами попросите ИТ опубликовать справочник «Виды внутренних документов» в OData (шаг 2 сценария развёртывания).

9. Сопоставление реквизитов по документу-образцу

Сопоставление создаётся по живому документу: в таблице загруженных документов нажмите ⇄ — откроется форма со всеми реквизитами этого документа и их значениями.

Колонка формыЧто в ней
Реквизит документа 1Симя реквизита, как оно пришло из OData (Number, Контрагент…)
Данные документазначение реквизита в этом конкретном документе — удобно понять, что вообще лежит в поле
Реестр панелиОАО / ОПАиЗ / ОВРК или «не переносить»
Реквизит реестравыбирается из колонок выбранного реестра: ОАО — заголовки Excel, ОПАиЗ — поля таблиц, ОВРК — поля договора

Реквизиты с готовым сопоставлением подсвечены зелёным. Кнопка + у реквизита добавляет строку — так один реквизит документа можно переносить сразу в несколько реестров. «Сохранить сопоставления» перезаписывает набор сопоставлений этого типа документа целиком (строки «не переносить» снимают сопоставление).

Если для одного типа документа сопоставлено несколько реестров, при переносе они заполняются из одного документа и синхронизируются между собой по GUID документа 1С — один документ 1С = связанные строки в разных реестрах.

Раньше сопоставление велось отдельными карточками «Сопоставление реквизитов и синхронизация» и «Сопоставление реквизитов документов» — они скрыты, накопленные там сопоставления продолжают работать.

Колонка таблицы сопоставленияПример
Тип документа 1СIDOC:705ef4c3-… («Заявка на закупку») или Document_ЗаказПоставщику
Реквизит документа 1СКонтрагент, СуммаДокумента
Тип реестра панелиОВРК
Реквизит реестра панелиОАО — заголовок колонки Excel; ОПАиЗ — заголовок или ключ колонки таблицы; ОВРК — заголовок или ключ поля договора: Примечание (= note), Номер заявки 1С (= n1c)

Реквизиты реестра можно вписывать ключом или заголовком — панель поймёт оба варианта. Дубли «тип + реквизит 1С + реестр» не создаются.

9. Перенос документов в реестры

Кнопка «→ Перенести в реестры» в карточке загрузки. Работает только с уже загруженными документами — подключение к 1С в этот момент не нужно.

Как находится строка реестра

По ключу: значение реквизита документа-ключа сравнивается со значением реквизита реестра-ключа. Если ключ реестра не задан, по умолчанию: ОАО — «Номер и Дата публикации», ОПАиЗ — «Номер заявки 1С» (n1c), ОВРК — «Номер договора» (cnum). Для ОПАиЗ выбирается и таблица («Электронные заявки», «Служебные записки 1С» и др.).

9. Типовые ошибки контура 1С

СообщениеПричина и что делать
1С ответила 404 на $metadataпубликация OData снята или адрес изменился: в конфигураторе заново опубликовать базу с флажком OData, перезапустить веб-сервер, сверить адрес в настройках источника (должен заканчиваться на /odata/standard.odata/)
База 1С недоступна / таймаутнет сети до сервера 1С или закрыт порт; проверить с компьютера панели: адрес должен открываться и отдавать XML/JSON
401 / отказ в доступеневерные логин/пароль пользователя 1С или нет права чтения объектов — проверить роли пользователя OData
Ответ 1С не похож на JSON/XMLадрес указывает не на OData-публикацию (например, на обычную страницу) — исправить адрес источника
Нет загруженных документов этого типаперенос работает по внутреннему хранилищу: сначала «Загрузить из 1С» за нужный период
В таблице сопоставления нет строкоткрыть загруженный документ кнопкой ⇄ и задать сопоставление реквизитов в форме-образце для этого типа документа и реестра
Строка не найдена (при переносе)значение ключа документа не совпало ни с одной строкой реестра: сверить ключ (лишние пробелы, другой формат номера) или сначала завести строку в реестре
Колонка «…» не найдена в реестререквизит реестра в сопоставлении не совпадает с реальным заголовком/ключом — поправить строку сопоставления (подсказки выдаются в модалке)
Реестр открыт в Excelзакрыть файл реестра и повторить перенос
Такая строка уже естьэтот реквизит 1С для этого реестра уже сопоставлен — отредактировать существующую строку вместо добавления
